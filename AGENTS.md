# AGENTS.md — opencode-rurout-v2

## Постоянное правило: локальный Colima CI (29 октября 2026)

По решению владельца для всех веток и изменений обязателен только локальный
Colima CI всех применимых областей на точном коммите **до push, создания PR
и merge**. Это основной порядок, не fallback; отдельно согласовывать замену
CI не требуется. В PR обязательна таблица команд/результатов с SHA; head PR
должен совпадать с проверенным коммитом. После любого изменения коммита,
включая rebase, повторить все применимые проверки. Частичная диагностика
не заменяет обязательные gates; красные проверки, SKIP и `NOT VERIFIED`
блокируют push/PR/merge. Ошибка или отсутствие окружения не делают gate
неприменимым. Для docs-only без применимых исполняемых проверок — статический
review diff с результатом и SHA в PR, без заявления о PASS тестов.

Согласование ресурсов, общая VM `cekasha-ci` 10ГиБ/6CPU, изоляция
source/deps/artifacts в Docker volumes, конечные согласованные лимиты и очистка
своих ресурсов по workspace `agent-rules/07-local-ci.md` сохраняются. Деплой —
только по прямому разрешению на конкретный выпуск и из merged source.

## Общие правила RuRout (обязательно прочитать первым делом)

Этот репозиторий — часть продукта RuRout и живёт в workspace `ai_router`.
Перед любой задачей прочитай `../../agent-rules/README.md` и все файлы,
на которые он ссылается. Ключевое:

- Каждое изменение без исключений: ветка `rurout/<topic>` от свежего
  `origin/main` → несколько коммитов → все применимые локальные Colima
  проверки на точном коммите → push ветки → PR в `main` с таблицей
  результатов и SHA → merge только проверенного коммита. Прод
  (сборка/деплой/публикация) — только по прямой команде пользователя и только
  из смерженного коммита.
- Продукт продаётся широкой аудитории: костыли и временные решения запрещены,
  чиним причину, покрываем тестами.
- Секреты не выводить и не коммитить; OpenAI OAuth-аккаунт — только
  последовательные запросы.
- Общение с пользователем — по-русски.

Main-ветка этого репозитория: `main`.
